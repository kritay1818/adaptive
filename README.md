# ADActive Pet — WordPress agent execution

עוזר שולחן־עבודה בצורת הלוגו של ADActive, עם חלונית שיחה בעברית. **הגרסה מבצעת קריאת עמודים/פוסטים אמיתית והכנת/ביצוע שינויי title/content דרך REST, עם אישור מפורש לכל כתיבה ואימות בקריאה חוזרת. יצירה היא טיוטה בלבד; עריכת תוכן מפורסם דורשת אזהרה ואישור. אין שליטה מלאה או עורך Elementor.**

פרטים מדויקים, מטריצת כלים/ספקים, approvals ומגבלות: [docs/WP-EXECUTION.md](docs/WP-EXECUTION.md). **למממש: [docs/HANDOFF.md](docs/HANDOFF.md)** — מצב בדיקות מדויק, חסימות, אבטחה ומסירת מקור ללא credentials. רשימת staging מפורשת: [docs/SOURCE-FILES.txt](docs/SOURCE-FILES.txt).

כלים: list/read/prepare-create/prepare-update לעמודים ולפוסטים; capabilities מאומתות; מדיה והגדרות לא־סודיות לקריאה בלבד. שינוי מופיע בכרטיס האתר/הפרויקט/המשאב עם snapshot ו־payload מדויק. **אישור וביצוע** שולח POST אחד ואז GET למזהה המדויק; **דחייה — ללא כתיבה** שולחת אפס POST. ללא WordPress מחובר: שיחת טקסט בלבד וללא כלים.

HTML/Gutenberg בסיסי ובטוח בלבד. אין scripts/styles/embeds, העלאות, עריכה חזותית מלאה של Elementor, מיגרציית אתר, התקנת plugins/themes, קבצי שרת, מחיקה, שינוי משתמשים, כתיבת settings, תשלומים/DNS או HTTP/shell כללי. יכולות admin אינן הוכחת שליטה מלאה; הרחבות שרת/Elementor דורשות connector מהימן נפרד.

## חיבור פשוט

1. פותחים את אייקון המפתח בשורת השיחה. בקרי פרויקטים נוספים נשארים מוסתרים.
2. באזור **WordPress · האתר שלך** מזינים כתובת אתר HTTPS סופית (אפשר אתר בתת־תיקייה), שם משתמש ו־**Application Password**. יוצרים סיסמת יישום במסך משתמשים → פרופיל ב־WordPress; לא משתמשים בסיסמת הכניסה הרגילה ולא מדביקים סודות בצ׳אט.
3. לוחצים **בדיקת חיבור**. נשלחת בקשת `GET index.php?rest_route=/wp/v2/users/me&context=edit` ביחס לכתובת התקנת האתר, עם Basic Authentication. מסלול זה תומך גם באתרים ללא קישורים קבועים יפים; הלוכסנים בפרמטר מקודדים בכתובת הבקשה. `context=edit` קובע את שדות התשובה; זו עדיין בקשת GET, ללא שינוי תוכן. הצלחה מאמתת את המשתמש בלבד, לא הרשאות פרסום או בניית אתר.
4. רק לאחר הצלחה נשמרים פרטי החיבור מוצפנים לפרויקט הנוכחי. כשל אינו מחליף חיבור קודם. מצב מחובר בפתיחה חוזרת פירושו **אימות קודם שנשמר**, לא בדיקת זמינות ברקע. ניתוק מוחק רק את פרטי האתר של אותו פרויקט; אינו מבטל את הסיסמה באתר עצמו.
5. בחלון **חיבור מודל** הנפרד מתפריט מגש המערכת בוחרים ספק, מזינים מפתח API בשדה ממוסך ולוחצים **טעינת מודלים מהספק**. בוחרים מהרשימה הנפתחת עם חיפוש — אין צורך להקליד מזהה מודל. Qwen מוגבל כאן למפתח מאזור Singapore; Kimi לפלטפורמה הבינלאומית. חיבור האתר נפרד לחלוטין. המפתחות והמודל הפעיל משותפים לכל הפרויקטים; פרטי האתר מבודדים לפרויקט.
6. טעינת הרשימה לאחר הזנת מפתח ממוסך אינה שולחת inference. בוחרים מודל ולוחצים מפורשות **חיבור מודל** לצד הודעת העלות כדי לשלוח בדיקה קצרה לספק. רק אחרי הצלחה המפתח נשמר מוצפן. אין כלי מחשב כללי. כלי WordPress המוגבלים מבצעים REST בפועל; credentials אינם נכנסים להקשר, אך תוכן אתר שנקרא בכלי כן מועבר כסימון נתונים לא מהימנים. מנוי לאפליקציית צ׳אט אינו מפתח API.
7. שורת הפקודה הרגילה נשארת מינימלית: שליחה, מפתח האתר וכפתור היסטוריה נפרדת; כפתור חיבור מודל מוצג בתחילת העבודה. תשובות רגילות אינן פותחות היסטוריה אוטומטית ואינן מגדילות את השורה. חיבור מודל זמין גם בחלון הנפרד בתפריט המגש. כרטיס כתיבה נפתח בחלון ההיסטוריה לאישור, בלי להחזיר בקרי מחשב/הגדרות לא קשורים. בהיסטוריה: העתקה, ייצוא `.md`/`.txt` דרך בורר קובץ native וצירוף הודעה כהקשר לבקשה הבאה (לא העלאת קובץ); ההקשר מוצג כשבב נשלף. פרטי endpoints, מקורות רשמיים, אבטחה ומגבלות: [docs/PROVIDERS.md](docs/PROVIDERS.md).

## מה נשמר ומה הושבת

- נשמרו החיה, המיתוג, גרירה, שינוי גודל, מיקום בין הפעלות, חלונית RTL, מגש המערכת, פרויקטים, שיחות, הקשר וכללים.
- הוסרו ממשטח העבודה הרגיל בקרי CRM, Drive, דואר, נתיבי Hermes, workspace ופרופילים.
- **שילוב Hermes/ACP הישן מושבת בפועל**, לא רק מוסתר: `main.cjs` אינו טוען או יוצר `HermesBackend`, אין IPC להפעלתו, וה־preload אינו חושף כלי ACP. `send` ו־`connect` דוחים בחירת Hermes ישנה בהודעה ברורה. אין fallback אוטומטי למודל בתשלום.
- קובצי Hermes היסטוריים, חיבורים מוצפנים, שיחות ופרויקטים קיימים אינם נמחקים או מועברים. הנתונים הישנים של ACP אינם מוצגים כשיחות API. חזרה ל־ACP תדרוש runtime מוגבל ואכיפה ייעודית ל־WordPress; תיקיית עבודה והסתרת UI אינן sandbox.
- קוד Hermes/ACP הישן (`src/hermes*.cjs`, בדיקות הפרוטוקול, המסמכים והסקריפט) הוסר מהמאגר. `main.cjs` ממשיך לדחות בחירת Hermes ישנה מקובץ מצב קיים; נתוני משתמש ישנים אינם נמחקים.

## אבטחת החיבור

- רשת מתוך main בלבד; renderer מקומי ללא remote loads, CDN, fetch, shell או IPC כללי. `sandbox`, `contextIsolation`, `webSecurity` פעילים, `nodeIntegration` כבוי. אימות IPC בודק חלון, תפקיד, main frame וכתובת מקומית מדויקת; החיה אינה רשאית לחבר אתר או לקרוא פרויקטים.
- `safeStorage` מצפין את **כל פרטי חיבור האתר**, כולל שם משתמש וסיסמה, ב־`wordpress-connections.json`, לפי מזהה פרויקט. אם הצפנת OS אינה זמינה או backend הוא `basic_text`, אין בקשת רשת ואין plaintext fallback. מפתחות המודלים נשמרים כ־safeStorage ciphertext נפרד לכל ספק/אזור ב־`connection.json` v2. קובץ OpenAI הישן נקרא ללא שינוי בפתיחה; ה־ciphertext שלו מועבר ללא אובדן רק בשמירה מוצלחת.
- מצב WordPress המוחזר ל־renderer כולל רק `connected`, `site`, `verifiedAt`, `encryptionAvailable`, ומפת capability בוליאנית מצומצמת. מצב המודל כולל מזהי ספק/מודל ורשימות ציבוריות בלבד, לא מפתחות. אין סיסמה, username או Authorization. גוף עמוד מוחזר רק בכלי קריאה ייעודי; שגיאות ונתוני משתמש נוספים אינם מוחזרים. השדות הממוסכים מתאפסים בשליחה/סגירה; אין שמירה ב־localStorage/sessionStorage ואין לוג סודות. JS אינו מבטיח איפוס פיזי של זיכרון; הסוד קיים זמנית בזיכרון וב־IPC בזמן חיבור.
- HTTPS בלבד, פורט 443, בדיקת TLS ברירת מחדל; ללא userinfo בכתובת, query, fragment או redirects. כל 3xx נדחה בלי בקשה ליעד ההפניה, כולל same-origin.
- DNS מוגבל לרשומות IPv4; כל כתובת מועמדת נבדקת מול טווחים פרטיים, loopback, link-local, CGNAT, documentation, benchmark, multicast ו־reserved. כתובת מאושרת מוצמדת ל־lookup של socket חדש (`agent:false`), כך שאין resolution נוסף בין בדיקה לבקשה. hostname המקורי נשמר לבדיקת TLS. IPv6, לרבות mapped/transition, חסום באופן שמרני; אתרים IPv6-only ורשתות מקומיות אינם נתמכים. אתר dual-stack יכול להשתמש ברשומת IPv4 ציבורית.
- deadline משותף של 15 שניות ל־DNS ולבקשה, תשובה עד 256 KiB, ללא דחיסה או retries אוטומטיים. תשובת שגיאה מהאתר אינה מוצגת ואינה נכנסת להיסטוריה. אין discovery באמצעות קישורים מתוך תגובת האתר.
- ההגנה אינה תחליף לאמון באתר ובתשתית DNS/TLS המקומית. כתובת ציבורית שהמשתמש בוחר מקבלת את פרטי האימות. אין ניטור background או הגנה מפני תוכנה זדונית שכבר שולטת במחשב.
- ניתוק מקומי אינו מבטל סיסמה ב־WordPress/מפתח אצל הספק, ואינו מבטיח מחיקה פורנזית מגיבויים. **שיחות והקשר נשמרים JSON לא מוצפן** ב־`app.getPath('userData')`. אל תדביקו סודות בשיחה/מסמכים. הקשר, כללים ועד 40 הודעות אחרונות נשלחים לספק המודל שנבחר; מסמכי ייחוס מסומנים כנתונים לא מהימנים, ללא הבטחת חסינות מהזרקת פרומפטים.

## הפעלה ובדיקות

```sh
cd /Users/simplevaad/Documents/ADActive-Pet
npm ci
mkdir -p artifacts
npm start
npm test
npm run test:ui
npm run check
```

נדרש Node.js 24+. הצעות שינוי שטרם אושרו קיימות בזיכרון main בלבד ומתבטלות ב־restart. גאומטריית החיה והשיחה נשמרת. אישורים קשורים ל־project/site/resource/page/payload/snapshot, חד־פעמיים ל־5 דקות; שינוי חיבור/פרויקט, resend, cancellation או דחייה מבטלים אותם. `wordpress-operations.json` שומר סיכומי פעולות, ללא credentials או תוכן גולמי. תוצאת כתיבה unknown חוסמת כתיבות לפרויקט גם לאחר restart, ללא retry; נדרשת בדיקה ידנית באתר ושחזור מבוקר, ו־UI לשחרור unknown עדיין אינו ממומש. זיהוי שינוי snapshot לפני POST אינו נעילה אטומית נגד עריכה בו־זמנית מצד לקוח אחר. התצוגה בדפדפן מסומנת כ־preview ואינה מאפשרת הזנת credentials או חיבור.

- בדיקות Node כוללות הצפנה, redaction, הפרדת פרויקטים, URL/SSRF, auth failures, דחיית redirects, הצמדת DNS ב־HTTPS transport ושימור החיבור הקודם.
- `npm run test:ui` מפעיל תרחישי חיבור, שיחה וכלים ב־**Electron אמיתי עם userData זמני מבודד**: WordPress onboarding, שיחה נפרדת ושימור נתונים, חיה/גרירה/גודל, וחמישה ספקי מודלים עם גילוי/אישור/בחירה/הצפנה. הצלחת WordPress והמודל משתמשת ב־**MOCK מוזרק ומסומן בלבד**, ולא בגישה לרשת. מופע המשתמש הקיים אינו מופעל מחדש.
- מצב מסירה נוכחי: 157 בדיקות unit עוברות ו־`npm run check` (formatting) ירוק. בדיקות ה־UI (`npm run test:ui`) דורשות Electron עם תצוגה ולכן מורצות ידנית.
- בניית Windows: `npm run build:win` מייצר מתקין NSIS (התקנה פר־משתמש, ללא הרשאות מנהל) וגרסת portable תחת `dist/`. ב־GitHub, דחיפת תג `v*` (התואם ל־version ב־package.json) מריצה את הבדיקות, בונה ומצרפת את הקבצים ל־release כטיוטה. חתימת קוד אופציונלית ומתועדת ב־`.github/workflows/release-windows.yml`.
- `artifacts/` הוא פלט בדיקות מקומי מוחרג מהמאגר, כולל צילומי MOCK; `tests/fixtures/` נשאר מקור ציבורי. יש ליצור artifacts לפני בדיקות UI ב־clone חדש.
- בדיקות provider משתמשות גם באחסון מדומה; תרחישי Electron מפעילים safeStorage אמיתי עם מחרוזות בדיקה פומביות. אי־זמינות הצפנה היא כשל, לא הצלחה מדומה.

**במשימת הפיתוח הזו לא בוצעו בקשות credentials חיות, inference בתשלום או שינויים באתר חי.** אימות native E2E השתמש ב־MOCK transports אך בלולאה, IPC, gate ו־REST אמיתיים: list → read → propose → deny (0 POST) / approve (1 POST + exact GET). ראיות: `artifacts/wp-agent-review-MOCK.png`, `wp-agent-review-narrow-MOCK.png`, `wp-agent-verified-MOCK.png`. אין מיגרציה מלאה, OAuth או כלי מחשב כללי. לא נבנה Windows חדש; `dist/` ותמונות ישנות אינם משקפים בהכרח את הגרסה הנוכחית. Windows runtime, נגישות מלאה וריבוי צגים פיזיים עדיין דורשים אימות נפרד.

## מקורות רשמיים שנבדקו

- [WordPress Authentication](https://developer.wordpress.org/rest-api/using-the-rest-api/authentication/): Application Passwords מאז 5.6, Basic Auth מעל HTTPS, יצירה במסך Edit User.
- [WordPress Users REST reference](https://developer.wordpress.org/rest-api/reference/users/): `GET /wp/v2/users/me`, פרמטר `context` בערכים view/embed/edit.

## קבצים מרכזיים

`src/main.cjs` — חלונות ו־IPC; `src/preload.cjs` — bridge מצומצם; `src/wordpress.cjs` — REST מאומת מוגבל לקריאה/כתיבה מאושרת; `src/wp-agent.cjs` — לולאת כלים ואישור מאובטח; `src/tool-adapters.cjs` — פרוטוקולי כלים לחמישה ספקים; `src/provider.cjs` — חיבורי מודלים מוצפנים ובחירה; `src/provider-adapters.cjs` — חמישה פרוטוקולים/ספקים; `src/core.cjs` — פרויקטים והקשר; `src/ui/` — UI מקומי; `tests/` — בדיקות; `artifacts/` — ראיות ותמונות. executor מוגבל לעמודים/פוסטים עם אישורים; אינו סוכן durable או admin כללי.
